# ADR-0002: طريقة حفظ البيانات وأمان الملفات (Data Storage & File Safety)

- **الحالة:** ✅ معتمد من مالك المشروع (2026-11-12)
- **التاريخ:** 2026-11-12
- **حالة الاختبار:** ✅ تم الاختبار والإثبات الآلي (100% نجاح في CI عبر Windows وmacOS وLinux)

---

## 1. السياق والمشكلة

البرنامج يتعامل مع نوعين من البيانات الحساسة للمستخدم:
1. **ملفات المستخدم الفعلية على سطح المكتب والمجلدات المربوطة:** أي خطأ في النقل أو الفرز قد يؤدي إلى فقدان ملفات المستخدم، وهو خط أحمر لا يمكن التسامح معه.
2. **بيانات التنظيم والإنتاجية المحلية:** مواقع الصناديق لكل شاشة، المجموعات، قواعد الفرز، المهام اليومية، الملاحظات الملتقطة (`Quick Capture`)، وسجل التراجع عن العمليات (`Undo Log`).

---

## 2. الخيارات المدروسة لحفظ البيانات

### الخيار الأول (المقترح): **قاعدة بيانات SQLite محلية (بوضع WAL) + تصدير نسخ احتياطية بصيغة JSON موقّعة البصمة + سياسة الفرز الآمن (Copy-Verify-Undo)**
- **الإيجابيات:**
  - **معاملات ذرية (ACID Transactions):** حتى لو انقطع التيار الكهربائي أو أُغلق الجهاز فجأة أثناء حفظ تخطيط الشاشات أو تسجيل عملية نقل ملفات، لن تتلف قاعدة البيانات (عكس ملفات JSON الخام التي قد تُكتب نصف كتابة فتتلف).
  - **بحث فوري سريع:** دعم فهرسة النصوص (`FTS5` في SQLite) للبحث في المهام والملاحظات وأسماء العناصر المربوطة في أجزاء من الألف من الثانية.
  - **خصوصية تامة (Local-First):** ملف قاعدة بيانات واحد في مجلد بيانات التطبيق الخاص بالمستخدم على كل نظام (`%LocalAppData%` في ويندوز، `~/Library/Application Support` في ماك، `~/.local/share` في لينكس)، وهو نفس النهج الناجح في مشروع **Jamrah**.
  - **شفافية النسخ الاحتياطي:** إمكانية تصدير واستيراد نسخة احتياطية كاملة بصيغة حزمة JSON مقروءة مع بصمة `SHA-256` للتحقق من سلامتها قبل الاستعادة.
- **السلبيات:**
  - يتطلب إدارة ترقيات الجداول (`Schema Migrations`) عند تحديث الإصدارات (وهو أمر مضمون وسهل عبر مكتبة `rusqlite_migration` أو `sqlx` في Rust).

### الخيار الثاني: **ملفات JSON مسطّحة فقط (Flat JSON Files)**
- **الإيجابيات:**
  - سهلة القراءة اليدوية بمحرر نصوص.
- **السلبيات:**
  - معرضة للتلف (`File Corruption`) عند الكتابة المتزامنة من عدة نوافذ/صناديق أو عند إغلاق النظام المفاجئ.
  - بطيئة جدًا عند زيادة عدد الملاحظات الملتقطة وسجل عمليات التراجع.

### الخيار الثالث: **قاعدة بيانات سحابية أو مزامنة خارجية إجبارية**
- **السلبيات:**
  - ينتهك مبدأ الخصوصية والعمل المحلي (`Local-First`) ويزيد تعقيد الأمان والمصادقة.

## 3. القرار المقترح وعقد أمان الملفات (File Safety Contract)

**نقترح اعتماد الخيار الأول: `SQLite` بوضع `WAL` عبر Rust (`rusqlite`)، مع التزام صارم بـ «عقد أمان الملفات» التالي المستلهم من `DeskBox`:**

1. **الربط الافتراضي أولًا (Virtual Mapping by Default):**
   - إضافة مجلد أو ملف إلى صندوق في البرنامج **لا ينقل الملف من مكانه الأصلي**، بل يحفظ مساره المرجعي فقط.
2. **المعاينة الإلزامية قبل أي نقل (Mandatory Dry-Run Preview):**
   - عند تشغيل «الفرز التلقائي لسطح المكتب»، يعرض البرنامج جدول معاينة يوضح المصدر والوجهة لكل ملف، ولا ينفّذ شيئًا إلا بعد ضغط المستخدم على «موافقة وتنفيذ».
3. **النسخ والتحقق قبل الإزالة (Copy-Verify-Then-Remove):**
   - عند نقل ملف فعليًا، يقوم البرنامج بـ:
     1. تسجيل العملية في جدول `undo_operations` بحالة `PENDING`.
     2. نسخ الملف إلى الوجهة الجديدة (مع عدم الكتابة فوق أي ملف موجود بنفس الاسم أبدًا، بل اقتراح اسم بديل آمن أو تخطّيه مع تنبيه واضح).
     3. حساب ومقارنة حجم الملف وبصمة `SHA-256` بين المصدر والنسخة الجديدة.
     4. فقط إذا تطابقت البصمة 100%، يُزال الملف من المصدر وتُحدّث الحالة إلى `COMPLETED`.
4. **التراجع بضغطة زر (One-Click Undo):**
   - يمكن للمستخدم التراجع عن أي دفعة فرز لإعادة الملفات إلى أماكنها الأصلية بدقة.
