# ADR-0001: اختيار الإطار البرمجي ولغات التطوير (Desktop Framework & Languages)

- **الحالة:** ✅ معتمد من مالك المشروع (2026-11-12)
- **التاريخ:** 2026-11-12
- **حالة الاختبار:** «لم يُختبر»

---

## 1. السياق والمشكلة

نحن نبني برنامجًا لتنظيم شاشة سطح المكتب يجمع بين صناديق الملفات (`Desktop Boxes`)، والكبسولة العلوية (`Top Capsule / Island`)، وأدوات الإنتاجية المحلية.  
شروط المشروع الأساسية هي:
1. أن يعمل بكفاءة عالية على **ويندوز (Windows)، ماك (macOS)، ولينكس (Linux)**.
2. أن يدعم **اللغة العربية (RTL) والإنجليزية (LTR)** بتصميم بصري أنيق وحركات سلسة.
3. أن يظل يعمل في الخلفية بأقل استهلاك ممكن للذاكرة والمعالج.
4. أن يوفّر أمانًا صارمًا عند التعامل مع ملفات المستخدم.

عند دراسة المشاريع المرجعية الثلاثة وجدنا:
- **DeskBox:** مبني بـ `C# + WinUI 3 + Windows App SDK + Rust DLL` — ممتاز في الأداء ولكنه **محصور في ويندوز فقط**.
- **Jamrah:** مبني بـ `.NET 9 MAUI Blazor Hybrid` — ممتاز في دعم العربية وSQLite ولكنه **لا يدعم لينكس رسميًا**.
- **Nova Island:** مبني بـ `Electron + C# Helper` — سهل في تصميم الكبسولة الزجاجية ولكنه **يستهلك ذاكرة عالية** بسبب تضمين متصفح Chromium كامل، ومربوط بأداة ويندوز فقط.

---

## 2. الخيارات المدروسة

### الخيار الأول (المقترح): **Tauri v2 (نواة خلفية بـ Rust + واجهة أمامية بـ TypeScript / React)**
- **الإيجابيات:**
  - **دعم رسمي كامل للأنظمة الثلاثة:** Windows وmacOS وLinux من نفس قاعدة الكود.
  - **خفّة فائقة في الموارد:** يستخدم محرك العرض المدمج في النظام (`WebView2` على ويندوز، `WebKit` على ماك، `WebKitGTK` على لينكس) دون شحن متصفح كامل، مما يجعل حجم الحزمة صغيرًا (~10–25 MB) واستهلاك الذاكرة منخفضًا جدًا مقارنة بـ Electron.
  - **أمان وموثوقية Rust في الخلفية:** لغة Rust تمنع أخطاء الذاكرة وتوفّر أداءً أصليًا (Native) في مراقبة المجلدات، حساب بصمات `SHA-256`، والتعامل مع SQLite — وهو نفس السبب الذي دفع `DeskBox` لكتابة طبقة الملفات الحساسة بلغة Rust.
  - **قوة Web UI في دعم العربية (RTL) والأنيميشن:** يتيح بناء كبسولة علوية وصناديق قابلة للطيّ مع دعم أصيل لخصائص CSS المنطقية (`RTL/LTR`).
  - **أمان مدمج من اليوم الأول:** نظام صلاحيات (`Capabilities & ACL`) في Tauri v2 يمنع الواجهة من الوصول لأي ملف أو أمر نظام غير مصرّح به.
- **السلبيات:**
  - يحتاج إلى إعداد مبدئي لبيئة Rust وNode.js معًا في CI (وهو أمر قياسي ومدعوم جاهزًا في GitHub Actions).

### الخيار الثاني: **Electron (Node.js + TypeScript / React)** *(المستخدم في Nova Island)*
- **الإيجابيات:**
  - توحيد اللغة (TypeScript في الأمام والخلف)، وتطابق محرك Chromium على الأنظمة الثلاثة.
- **السلبيات:**
  - حجم تنزيل ضخم (120–200 MB) واستهلاك ذاكرة مرتفع لبرنامج يفترض أن يعمل طوال اليوم في الخلفية على سطح المكتب.
  - التعامل المباشر مع نوافذ النظام والملفات في Node.js أقل أمانًا وأداءً من Rust.

### الخيار الثالث: **.NET 9/10 + Avalonia UI (C#)** *(بديل متعدد الأنظمة لـ WinUI 3 وMAUI)*
- **الإيجابيات:**
  - يعمل على ويندوز وماك ولينكس، ولغة C# مألوفة وقوية.
- **السلبيات:**
  - بناء حركات الكبسولة الزجاجية المرنة (مثل `Nova Island`) وتخصيص CSS ثنائي الاتجاه (RTL/LTR) في Xaml أعقد وأبطأ تطويرًا من تقنيات الويب الحديثة.

### الخيار الرابع: **Flutter Desktop (Dart)**
- **الإيجابيات:**
  - محرك رسم موحّد ودعم جيد لـ RTL.
- **السلبيات:**
  - دعم النوافذ المتعددة الشفافة العائمة (Multi-Window Desktop Widgets & Top Island) في Flutter Desktop لا يزال أقل نضجًا على Linux وmacOS مقارنة بـ Tauri v2.

---

## 3. القرار المقترح والسبب

**نقترح اعتماد الخيار الأول: `Tauri v2` مع `Rust` للنواة الخلفية و`TypeScript + React + Tailwind CSS` للواجهة الأمامية.**

**لماذا هذا الخيار هو الأنسب؟**
لأنه يجمع أفضل ما في البرامج الثلاثة التي درسناها دون عيوبها:
1. يأخذ من **DeskBox** قوة وأمان **Rust** في إدارة الملفات وحمايتها من التلف.
2. يأخذ من **Nova Island** مرونة وسلاسة واجهات الويب في رسم الكبسولة العلوية والصناديق، ولكن **بجزء بسيط من استهلاك الذاكرة** بفضل Tauri v2 بدل Electron.
3. يأخذ من **Jamrah** جمالية الواجهة العربية (RTL) والتخزين المحلي في SQLite، مع كسر حاجز النظام الواحد ليعمل على **Windows وmacOS وLinux** معًا.
